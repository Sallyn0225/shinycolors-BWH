# UI 与交互规范

本规范把 PRD 转为可执行界面约束，不规定组件库实现。设计方向是“角色资料感 + 清晰数据编辑界面”，不是营销落地页。

## 1. Design Read

面向《闪耀色彩》粉丝的数据查询型静态应用。真实头像、组合图标、日文名称和有证据的代表色提供角色识别；中性底色、清晰层级和紧凑数据行保障阅读。

设计参数：

- `DESIGN_VARIANCE: 4`
- `MOTION_INTENSITY: 2`
- `VISUAL_DENSITY: 7`

因此不采用 AIDA、超大 Hero、滚动叙事、玻璃拟态、重阴影、GSAP 或持续动画。

## 2. 页面框架

### 顶部栏

- 高度 64 至 72px，桌面保持单行。
- 左侧为文字产品名，不仿造官方 Logo。
- 中间或右侧为总榜、组合榜、双人对比。
- 最右侧为主题选择，支持系统、浅色、深色。
- 移动端允许产品名缩短，导航仍为三项横向标签，不使用汉堡菜单。

### 内容容器

- 最大宽度 1360px。
- 桌面左右内边距 32px，平板 24px，手机 16px。
- 页面标题与一句说明纵向排列，说明控制在两行内。
- 页面标题区不是 Hero，不占满首屏。

### 页脚

显示：

- 数据单位为 cm。
- 数据来源与最后核验日期。
- 官方偶像索引链接。
- “非官方粉丝数据工具，角色与作品权利归原权利方所有。”

## 3. 视觉 token

实现时使用 CSS 自定义属性，禁止组件内散落硬编码主题色。

### 必需 token

```text
--surface-page
--surface-panel
--surface-muted
--surface-hover
--text-primary
--text-secondary
--text-muted
--border-subtle
--border-strong
--focus-ring
--control-active
--track
--chart-grid
--chart-halo
--danger
```

代表色来自数据对象的 `representative_color.hex`，不进入全局 token。

### 主题

- 默认 `system`，可手动切换。
- 浅色和深色保持相同信息层级，不做分段反色。
- 避免纯黑 `#000000` 和纯白 `#ffffff` 作为大面积页面底色。
- 页面功能强调色保持单一，代表色只承担身份识别和数据系列用途。

### 字体

采用无需网络下载的系统字体栈，优先覆盖日文和简体中文：

```text
"Noto Sans JP", "Noto Sans SC", "Hiragino Sans",
"Yu Gothic UI", "Microsoft YaHei", system-ui, sans-serif
```

- 日文主名：正文同级或高一级字重。
- 英文副名：小一级、次级色。
- 数字：启用 `tabular-nums`。
- 不使用衬线体或在线字体依赖。

### 圆角和阴影

- 数据面板：12px。
- 输入、选择器、按钮：8px。
- 紧凑状态标签可使用全圆角。
- 主要依靠边框和留白分层，只在悬浮层使用轻微背景同色阴影。

## 4. 控件规范

### 维度选择器

使用三段式单选控件：

- 胸围 B
- 腰围 W
- 臀围 H

每项同时保留中文和字母，不能只显示 B/W/H。键盘方向键可切换，当前项不只靠颜色表达。

### 排序器

单一控件表达升序和降序，标签明确为“从高到低”“从低到高”。图标只能辅助，不能替代文字或无障碍名称。

### 组合选择

总榜使用原生 `<select>` 或样式克制的可访问选择器。选项显示日文组合名，英文名作为补充。首项为“全部组合”。

### 搜索框

- 可见标签“搜索成员”。
- placeholder 示例“输入日文名或英文名”，但不代替标签。
- 有输入时显示清除按钮。
- 不加入远程搜索、建议列表或加载态。

### 成员选择器

- 使用原生 `<select>` 和 `<optgroup>` 即可，28 项无需自定义虚拟列表。
- 每组按 JSON 原始顺序显示成员。
- 已在另一侧选中的成员禁用。
- 选择器旁展示当前成员头像和代表色色标。

### 按钮状态

所有按钮包含默认、hover、active、focus-visible、disabled。active 可做 1px 位移或轻微缩放。禁用态仍需可辨识。

## 5. 总榜布局

### 桌面数据行

建议列：

```text
名次 | 成员 | 组合 | B | W | H | 当前维度可视化 | 来源
```

- 当前维度的数字和列标题强化。
- B/W/H 不重复显示单位，表头注明 cm；当前主值可显示 `86 cm`。
- 头像固定 54x54，避免 CLS。
- 不为每行同时加上下边框，只使用行间单一分隔或背景变化。
- 悬停时轻微改变行背景，不移动布局。

### 进度条

- 中性轨道、成员代表色填充。
- 高度建议 8 至 10px。
- 最小值 12%，最大值 100%。
- 填充宽度变化只在用户明确切换维度时做 150 至 220ms 过渡。
- 过滤和搜索后，仍使用全局尺度。
- 近白代表色在填充外加 1px 中性边界，不改原始颜色。

### 移动数据行

每个结果重排为一个数据行块：

1. 第一行：名次、头像、日文名、英文名。
2. 第二行：组合图标与组合名、当前维度主值。
3. 第三行：进度条。
4. 第四行：B/W/H 紧凑值、官方来源链接。

数据行之间使用一个分隔面，不堆叠浮夸卡片阴影。

### 结果摘要和空状态

- 摘要示例：“共 28 名成员”“アンティーカ，共 5 名”。
- 摘要区域使用 `aria-live="polite"`，搜索输入时避免逐键冗长播报。
- 空状态直接说明筛选条件无结果，并提供恢复操作。

## 6. 组合榜布局

### 桌面

8 个组合使用排名数据行，不做 8 张营销卡片。建议列：

```text
名次 | 组合 | 成员数 | 当前平均值 | 成员范围 | 可视化 | 查看成员
```

- 色条或可视化填充使用组合代表色。
- 平均值显示 1 位小数。
- 查看成员链接跳转到带查询参数的总榜。

### 组合可视化尺度

使用 8 个组合当前维度平均值中的最小和最大值做页面内排序辅助。因为对象是组合平均值而不是成员值，应在组件标签中明确“组合平均值”。若希望跨页面绝对对照，可改用成员全局尺度，但首版不要同时展示两种尺度。

推荐公式仍使用 12% 至 100% 视觉区间：

```text
widthPercent = 12 + 88 * (average - unitAverageMin) / (unitAverageMax - unitAverageMin)
```

筛选仅有维度，不会出现同一维度内尺度漂移。若全部平均值相同，统一 100%。

### 移动

- 每个组合独立一行块。
- 组合图标 40x40。
- 名次、组合名、平均值在首行。
- 成员数、范围、可视化和跳转在后续行。

## 7. 双人对比布局

### 选择区

- 桌面为 A 和 B 两列，中间放交换按钮。
- 移动端为 A、交换按钮、B 的纵向顺序。
- 未选成员时使用明确空态，不显示灰色假头像。

### 身份区

每侧显示：头像、日文名、英文名、组合、代表色色标、官方资料链接。A/B 标签始终可见，不能只依赖左右位置。

### 雷达图

- 原生 SVG，宽高随容器，`viewBox` 固定正方形。
- 三角轴依次为 B、W、H。
- 网格最多 4 层，避免视觉噪声。
- A/B 图形使用各自成员代表色。
- 为每条代表色线先绘制较宽的中性 halo，再绘制原色细线，保证 `#fbfafa` 等颜色可见。
- A 使用实线加圆点，B 使用虚线加菱形。
- 填充使用原色低透明度，重叠后仍能辨识。
- 不做 hover 才能读取的唯一 tooltip。轴旁或下方表格始终展示原始值。
- SVG 有简短可访问名称，完整信息由数据表格提供。

### 数值表

固定三行 B/W/H，列为维度、A、B、A-B。正差值带 `+`，零显示 `0 cm`。移动端允许表格紧凑，但不能隐藏差值。

## 8. 代表色使用矩阵

| 场景 | 使用成员色 | 使用组合色 | 辅助规则 |
|---|---|---|---|
| 成员头像边框 | 是 | 否 | 近白色加中性外边界 |
| 总榜进度填充 | 是 | 否 | 文字仍用语义 token |
| 组合图标底板 | 否 | 是 | 只做低面积身份识别 |
| 组合榜可视化 | 否 | 是 | 轨道中性 |
| 雷达 A/B | 是 | 否 | halo、线型、点形共同区分 |
| 按钮背景 | 否 | 否 | 使用固定可访问控制色 |
| 正文文字 | 否 | 否 | 使用语义文本 token |
| 焦点环 | 否 | 否 | 使用固定 focus token |

颜色值和冲突处理见 `docs/COLOR-SOURCES.md`。

## 9. 状态完整性

### 加载

核心数据随构建打包，通常不出现异步加载。禁止为不存在的网络等待加入骨架屏。

### 空状态

- 总榜搜索无结果。
- 对比页未选 A、未选 B、只选一人。

### 错误状态

- 数据开发断言失败时，在开发环境给出明确错误，不静默显示部分榜单。
- 生产构建若核心数据无法导入，应用显示简短错误边界和刷新提示。
- 外部来源链接失效不阻断核心页面。

### 非法 URL

页面先解析为合法状态，再渲染，并通过 replace 规范化 URL。不能先显示错误状态再闪回默认状态。

## 10. 动效

只允许：

- hover、focus、active 反馈。
- 维度切换时进度条宽度过渡。
- 路由或筛选结果的轻微 opacity 过渡，可省略。

全部动效只改变 transform 或 opacity，进度条宽度是用户明确请求的数据过渡例外。`prefers-reduced-motion: reduce` 下关闭非必要过渡。

不使用 Motion、GSAP、滚动监听、无限循环、视差、marquee 或入场编舞。

## 11. 响应式检查表

### 320px

- 无页面级横向滚动。
- 三项导航可读。
- 控件标签不截断。
- 数据行按四层结构重排。
- 雷达图保持正方形且标签不裁切。

### 768px

- 控制区最多两行。
- 触控目标不缩小。
- 对比图和表上下排列。

### 1440px

- 内容不无限拉宽。
- 表格列有明确对齐。
- 主值、图形和来源链接都在首屏后的合理阅读区域。

## 12. 预检

实现完成前必须确认：

- 日文主名、英文副名和中文 UI 层级一致。
- 所有代表色来自数据，不由组件猜测。
- 近白色在两种主题均可见。
- 所有按钮文字通过 WCAG AA。
- 所有输入有可见标签。
- 没有只靠颜色表达排名、A/B 或当前选择。
- 没有重动画和页面级横向滚动。
- 浅色、深色、系统主题均测试。
- 320px、768px、1440px 均测试。
- 完整键盘流程均测试。
